# 💰 Интерактивный CLI-контроллер управления личными финансами

Итоговое домашнее задание по дисциплине **«Программирование на TypeScript и библиотеки фронтенд разработки»** (ВШЭ ФС).

Консольное приложение на **TypeScript** с использованием библиотеки **`inquirer`** для интерактивного управления бюджетными счетами, финансовыми транзакциями, аналитикой и экспортом отчётов в CSV.

---

## ✨ Возможности приложения

### 1. Основной функционал
- **Главное меню**: наглядная таблица всех бюджетных счетов, общий баланс, выбор счёта для детального просмотра, создание нового счёта и выход из программы.
- **Создание нового счёта с уникальным ID**: интерактивный ввод названия счёта с валидацией (проверка длины и уникальности имени), автоматическая генерация уникального идентификатора (`acc-...`), а также возможность сразу задать начальный остаток.
- **Просмотр выбранного счёта**: отображение текущего баланса, суммы доходов/расходов и отсортированной таблицы всех транзакций счёта.
- **Добавление транзакции**: пошаговый интерактивный ввод через `inquirer` (выбор типа `income` / `expense`, ввод суммы с поддержкой дробной части, выбор категории из списка или ввод собственной, ввод даты `ГГГГ-ММ-ДД` с проверкой календарной корректности, ввод описания) и автоматический возврат к счёту.
- **Удаление транзакции**: выбор транзакции из списка, запрос подтверждения удаления (`confirm`) и возврат к счёту.
- **Удаление счёта**: запрос подтверждения удаления, полное удаление всех транзакций счёта и самого счёта с возвратом в главное меню.
- **Экспорт счёта в CSV-файл**: корректная выгрузка всех транзакций счёта в стандартный формат CSV (RFC 4180) с кодировкой UTF-8 с BOM (`\uFEFF`) для корректного отображения кириллицы в Microsoft Excel, LibreOffice и Numbers.

### 2. Дополнительные возможности
- **Автоматическое сохранение данных (JSON Persistence)**: все изменения счетов и транзакций автоматически сохраняются в файл `data/accounts.json` и восстанавливаются при следующем запуске.
- **Предзаполненные демонстрационные счета**: при первом запуске приложение уже содержит 3 реалистичных демо-счёта с транзакциями (а также функцию сброса к демо-данным из главного меню).
- **Редактирование транзакций и переименование счетов**: возможность изменить сумму, тип, категорию, дату или описание любой существующей транзакции, а также переименовать счёт.
- **Расширенная аналитика и статистика**: расчёт средних чеков, визуальные индикаторы соотношения доходов/расходов и разбивка по категориям с долями в процентах (как по отдельному счёту, так и по всем счетам сразу).
- **Поиск и многокритериальная фильтрация транзакций**: фильтрация операций счёта по типу (доход/расход), ключевому слову в описании или категории, диапазону дат (`С` — `ПО`) и диапазону сумм.
- **Цветной табличный интерфейс (`chalk`)**: цветовая индикация доходов (зелёный) и расходов (красный), псевдографические таблицы и очистка экрана `console.clear()` при переходах.

## 🚀 Установка и запуск проекта

### Предварительные требования
- Установленный **Node.js** (рекомендуется версия 18.x или выше) и пакетный менеджер **npm**.

### 1. Клонирование репозитория и установка зависимостей
```bash
git clone https://github.com/khoshov/typescript-homework.git
cd typescript-homework
npm install
```

### 2. Запуск интерактивного приложения (в режиме разработки через `ts-node`)
```bash
npm start
```
*(или `npm run dev`)*

### 3. Сборка TypeScript в JavaScript и запуск production-версии
```bash
npm run build
npm run start:prod
```

### 4. Проверка строгой типизации и запуск автотестов
```bash
npm run typecheck
npm test
```

## 🛠️ Технические особенности реализации

1. **Строгая типизация TypeScript (`strict: true`)**:
   - Включены все флаги строгой проверки типов (`noImplicitAny`, `strictNullChecks`, `strictPropertyInitialization`, `noImplicitReturns` и др.).
   - Полное отсутствие `any`.
   - Использованы `interface`, `enum`, `type`, модификаторы доступа (`public`, `private`) и `readonly`-свойства.
2. **Валидация пользовательского ввода**:
   - **Сумма**: проверка на положительное число (до 2 знаков после точки или запятой).
   - **Дата**: проверка формата `ГГГГ-ММ-ДД` и реального существования даты в календаре (с учётом количества дней в месяце и високосных лет).
   - **Название счёта**: проверка длины (от 2 до 50 символов) и отсутствия дубликатов.
   - **Имя CSV-файла**: проверка на отсутствие запрещённых символов файловой системы.
3. **Формат CSV-экспорта**:
   - При экспорте счёта автоматически создаётся CSV-файл (по умолчанию в каталоге `exports/`).
   - Все поля со спецсимволами (запятыми, кавычками) экранируются по стандарту RFC 4180.
